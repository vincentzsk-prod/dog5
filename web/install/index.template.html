What can be written (the target range)

Flash rangeWhat happens
0x000000–0x003FFFBoot head (bootloader, chip key). Never written by the update loader.
0x004000–0x092FFFThe app area. The update loader rewrites only the 4 KB sectors that differ, and reads each one back.
0x0E0000–0x0E4FFFStep 1 only: a staged copy of the loader and its update record, written by the firmware that is running now, erased when the update finishes.
everything elseNot written.

This page cannot write flash. It answers the unit's read requests with bytes from the package, and refuses a request outside the package. The loader checks the package against this unit's own chip key before it erases anything (source: firmware/loader/ldr_core.c). Step 1 is done by the unit's running firmware; for a stock unit that code is not in this repository, so what it does is unverified here.

If something goes wrong

Unplug the USB cable, power-cycle the FM-1, and run this page again. A unit that was cut off in step 2 starts in update mode; this page then offers Resume. If the unit will not boot, use M-Flasher with your backup. Nothing more ambitious than that is promised here: app-level USB rescue is unproven on this hardware.

Not tested against a real unit by the author of this page. It runs from https:// or http://localhost (WebMIDI's rule); a downloaded copy of this file works the same when served that way, and makes no network request of any kind.
