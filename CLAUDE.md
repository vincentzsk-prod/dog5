# DØG-5 — BUILD BRIEF (read this first)

**This repo is a fork of OberVave, being turned into DØG-5.** This brief is the operating truth for
the build. Where it conflicts with anything in the preserved OberVave notes (`dog5-docs/CLAUDE.obervave.md`) or in
the base code, **this brief wins.** Full reasoning for every decision here lives in `dog5-docs/` — this is the
summary a fresh session needs before touching anything.

**Last updated:** 18 Nov 2026 (Batch 15 write-lock), by Vincent Kruger (DØGS) with Claude. First assembled 27 Oct as an
account-transition handoff — treat `dog5-docs/` as the complete project record.

---

## 1. WHAT DØG-5 IS

Custom firmware for the **M-VAVE FM-1** pocket synth, forked from **OberVave** (an 8-voice analog-style
polysynth). It turns the FM-1 into an aggressive, live, virtual-analog voice for the band **DØGS**
(bubblegum egg punk / garage psych), and it is released **free and open-source (GPL-3.0-only)**.

Its one unique idea: **the on-screen character is a dog, and his bark IS the live oscilloscope** — the
real waveform of whatever you're playing fires out of his open mouth. "The sound you shape is the sound of
his bark." Nobody else in the FM-1 scene has made the readout *be* the character; that fusion is the moat.

## 2. PRIME DIRECTIVE + HARD BUILD RULES

**TONE IS KING.** Features and presets are negotiable; tone and functionality never are. Given a choice
between more features and better sound, sound wins. This settles every scope argument.

Second rule: **this is a LIVE instrument.** Navigation and ease-of-use in the dark, mid-performance, are a
top priority. Simplicity beats cleverness.

**Non-negotiable technical rules (break these and you brick the unit or the build fails):**

- ⚠️ **Build with `-Os`, NEVER `-O2`.** At `-O2` the FM-1's USB-MIDI endpoint babbles, the USB hub disables
  the port, and **no installer can get another firmware back on** (a brick-class trap). Upstream lost days
  to this; the exact offending line was never found. `-Os` is mandatory.
- **No 64-bit division** anywhere (`tools/build.py` checks and refuses). 64-bit multiply is fine.
- **Integers only — the chip (JieLi AC791N) has no FPU.** The whole engine is fixed-point. Tables are
  generated by `tools/gen_tables.py`.
- **RAM ≤ 96 KB**; big buffers go in `.pool`.
- **Audio ISR budget:** 256 frames @ 44.1 kHz = 5.8 ms per call; stay under half. Device render time shows
  on the GLOBAL page in µs (budget 5800, aim < 2900). Measure on the device before trading any sound quality.
- **Do not overclock** (the 320 MHz option dropped some FM-1s into UBOOT; upstream removed it).
- Rescue (hold OCT− at power-on) is **unproven** on this hardware — the second FM-1 is the real insurance.

## 3. THE LOCKED BASE — pin and own, do not track

```
Base:    zvenson/obervave
Tag:     v1.5.3
Commit:  7e1ccf9ca9e96a14a961e48ea8fe6efa907422df   (released 2026-10-19; tested twice on a real FM-1)
Identity:FM-1_955
```

v1.5.3 was chosen because it is both the newest release AND the best device-tested one (1.5.1 is only a CI
rebuild of 1.5 — no new code; 1.4.2 was never device-tested).

**Fork discipline:** upstream shipped 1.2.1 → 1.5.3 in six days and DØG-5 rewrites the panel and deletes
the sequencer, so **we do not merge upstream.** Keep `upstream` as a fetch-only remote and cherry-pick
specific fixes deliberately if ever needed. The base is ours and has stopped moving. Keep an off-GitHub
`git bundle` backup too.

**Exactly one upstream exception so far** — DØG-5 stays pinned to v1.5.3 except for upstream `36df696`
(cherry-picked with `-x`): accept the UC25HQ80 flash (JEDEC `0xB36014`, newer AliExpress FM-1s) in
`FL_JEDEC_OK` beside the Puya P25Q80, so those units save to flash and take updates instead of RAM-only.
One line, no effect on the program-sector / flash-write logic. Upstream OberVave 3.x history is recorded in
our branch (a `-s ours` merge) but **no 3.x code is taken.** Candidate to hand-port later, **only after a
listening test on the device, not now:** the four-pole ladder filter + soft stages (upstream `66ef5b0`) —
its DSP (`obv_dsp.h`) is self-contained, but the engine hookup needs a manual port (3.x's `part_t` diverged).

## 5. THE SCREEN & UI ARCHITECTURE

**HOME is the live PERFORM page** (CUTOFF, RESO, ENV AMT, RELEASE on the four knobs), styled in the current
chapter. Pressing HOME from anywhere snaps back to it. This is inherited and already works — do not change it.

**The knob readout is Monologue-style (transient), NOT a permanent HUD.** The art (dog, beam, field, bottom
bar) is the resting HOME screen. Turn a knob → its value pops over the art briefly (via `say()`/`toast`),
then decays and the art returns. The bar is never permanently filled with live values.

**The bottom bar carries ONLY the preset number + preset name** (e.g. `17 TITANIC`). No dog name (we know
his name), no knob values. Legible 16px font (`FONT_S`/Terminus). It is the one element that never degrades
and is never broken by the fracture — **top of the screen breaks, the bottom bar is sacred.**

**Pages = 21** (**DONE**, `PAGE[]` in `obv_params.h`; Batch 9B added MIXER and re-dealt the EDIT knobs; VOICE + carries `P_POLY_N`), a table edit (one row each; no parameter id moved, the patch record is untouched):

| Family | Button | Pages |
|---|---|---|
| LIVE | HOME | HOME (dog/beam/field/bar) |
| Voice | EDIT | OSC 1 · OSC 2 · MIXER · OSC MOD · FILTER · FILTER + |
| Envelopes | ENV | FILTER ENV · AMP ENV |
| Modulation | LFO | LFO · LFO DEST · LFO + |
| Psych Chain | FX | DRIVE · BBD DELAY · SPRING · TAPE |
| Arp | ARP | ARP |
| System | GLO | GLOBAL · VOICE · VOICE + · OUTPUT |

(VOICE splits into two pages to fit the polyphony control — §6. The **sequencer is deleted**, freeing SEQ,
ALGORITHM, PLAY, REC.)

**The EDIT pages' knobs (Batch 9B, `PAGE[]`; `-` = no knob):** OSC 1 = WAVE · PW · - · - ; OSC 2 = WAVE · PW · SEMI · FINE ;
MIXER = O1 LVL · O2 LVL · NOISE · DRIVE (the pre-filter `P_DRIVE`, not GROWL; the two levels are labelled O1 / O2 LVL
because "LEVEL" twice on one page said nothing) ; OSC MOD = SYNC · X-MOD · ENV>O2 · - ; FILTER = RESO · ENV AMT · MORPH · TYPE ;
FILTER + = KEY TRK · VEL>FLT · VEL>AMP · -. HOME (PERFORM) is unchanged: CUTOFF · RESO · ENV AMT · RELEASE.

**Hold EDIT + a black key = jump to a page (Batch 9B; `keys_in`, `EDIT_KEY[]`, tests/controls/edit_keys.txt).** The keybed's 11
black keys read, from F3, in groups 3·2·3·2·1 = the unit's printing OP1 OP2 OP3 · OP4 OP5 · OP6 PIT GLO · MONO POLY · (none):
OP1 = OSC 1, OP2 = OSC 2, OP3 = MIXER, OP4 = FILTER (again: FILTER +), OP5 = VOICE, OP6 = VOICE +, PIT = OSC MOD,
GLO = GLOBAL (again: OUTPUT), MONO / POLY = the patch's MODE (header readout `MODE MONO`). The shortcut never sounds a note and
sends no MIDI; the key right of POLY (F#5) stays a note. A jump updates the family's remembered page. A tap on EDIT still cycles
the family, now **on release** (suppressed if a shortcut was used during the hold).

**SELECT (Batch 9B):** on HOME with no layer held, a turn is `P_LFO_RATE`, 2 a detent, clamped 0..127, a real parameter (SAVE
stores it), header readout `LFO RATE 4.2Hz` for a second; on every other page it does nothing. The old always-on tempo scroll
is gone: the tempo is GLOBAL knob 1 and the MIDI clock. SAVE armed + SELECT pressed = the dice, and SELECT held on a Psych page =
the "+" knobs, both as before.

**REC (WAG) = HOLD (Batch 9B):** a press with no layer held, on any page, toggles the same latch as the ARP button on its page
(`hold_toggle`; ORed with the sustain pedal in `part_sus`); the REC LED shows it. STOP (PLAY) releases it when it engages, and so
does a MIDI panic, CC 123 / 120 (Batch 13); a patch change and the pedal do not. REC's tap tempo (`alley_tap`) is gone; ALLEY's knob is unchanged.

**Adopted from Skiff** (the strongest navigation model in the scene; upstream already borrows from it):
- ⭐ **Hold HOME = a live control map** showing what every button/knob does on the current page. This is the
  answer to the renamed controls — no memorisation, no dual-labelling; the headers stay pure. **DONE**
  (`ui_map`/`draw_map`; tests/map.txt): held ≥ 350 ms it shows the page's four knobs and, per button, its dog name with the
  label printed on the panel ("DIG (EDIT)", "HOWL (ENV)" … "BARKS (PRESETS)"; FX and OCT have none in the brief) and where a
  press goes *now*; letting go stays on the page. **Batch 9B:** 13 rows under a 32 px head (`MAP_ROWS`): the six page buttons, HEEL (PLAY)
  STOP, FLOP (SEQ) HOLD=TAPE STOP, SLOBBER (ALGO) SLOP RIDE, WAG (REC) HOLD, then by page: on an EDIT-family page the three
  EDIT-held key lines, on HOME FETCH (SELECT) LFO RATE + BURY + BARKS, on a Psych page FETCH HOLD: X + + BURY + BARKS, elsewhere BURY +
  BARKS + OCT-/+. Dropped to fit: the HOME row and "FX HELD: THE 4 MACROS" (and OCT-/+ on HOME / Psych / EDIT pages). The page titles stay plain (FILTER, BBD
  DELAY…; HOME's is **DØG-5**, the owner's choice 2 Nov): the dog names live in the map only. A tap goes HOME **on release** (that is the cost: HOME no longer
  acts on press). The map draw calls `app_idle()` (DRAW RULE) — the host script asserts it.
- **Page families remember their last page** (one `uint8_t` each, `fam_last`) — so HOME→play→EDIT returns you to
  where you were, not to the top of the cycle. **DONE** (tests/families.txt, 43 `expect page` checks).
- Each parameter page **draws what its knobs affect** (envelope shape, LFO wave, etc.) — already DØG-5 law.

**OCT− / OCT+ = octave, always** (−2..+2, both = 0). Undo/redo was a sequencer feature and leaves with it.

**The live tricks — DONE** (global, live, no patch byte / CC; untouched = bit-exact; `listen/trick/`, tests/trick/):
**PLAY (HEEL) = STOP**, the kill switch — a tap: 5.8 ms fade at the master gate (after CHEW), then every voice, held
key, queued note and effect state cleared (`kill_clear`: `drive_clear`/`fx_clear`/`tape_clear`), PLAY LED + header
`STOPPED`; `KILL_MOMENTARY 1` makes it hold-to-silence. **SEQ (FLOP) held = TAPE STOP** (`obv_deck.h`) — on the
**whole mix**, one stage after everything (voices, GROWL, ALLEY, DRAIN, CHEW) and before STOP's gate: one motor, so the
repeats, the tail and the hiss dive with the voices. The speed falls linearly over half a bar at the tempo (0.5–1.1 s);
the mix is read back falling behind (tape's 6-point `tp_taps` read, a 557 ms line, pool +96 KB), one SVF low-pass
(`svf_lp`) closes 1.25× the dive (`TS_DIVE8`), level to silence below 1/3 speed; let go = the live mix back over 5.8 ms.
A/B'd against the approved per-voice render (`tests/trick/tapestop_ab.py`): the same pitch, brightness and level
through the dive; the stop is now silent. +140 host instr/sample while held (the per-voice one was +3), 0 at rest. **ALGORITHM (SLOBBER) = the SLOP ride** — **final depth 2x** (chosen
by ear 3 Nov from 1x / 1.5x / 2x, `listen/trick/slop_depths/`; `SLOP_SCALE_X2 4`): the encoder's 0..127 doubled, i.e.
0..254 *added* to the patch's VINTAGE (sum ≤ 381), glides ~23 ms, never stored, 0 at power-on; header
`SLOP +N = VINTAGE M` for 1 s. **Known, accepted character trait — heard and approved, NOT a bug, do not "fix" it:** at
full ride each voice card sits off true by its own VINTAGE offset — voice card 0 (all MONO/UNISON notes) ~20 cents
flat (≈10 at the old 1x, doubled at this range), other cards sharp (a chord averages ~3 cents flat), plus the wander. The hold-HOME
map lists the three tricks (Batch 9B).

**Control renames (the dumb-dog register, function unchanged):** ALGORITHM=SLOBBER, ENV=HOWL, SEQ=FLOP (now TAPE STOP), PLAY=HEEL, REC=WAG, GLO=FLEAS, ARP=ZOOMIES, LFO=PANT, SAVE=BURY, EDIT=DIG, SEL=FETCH,
PRESETS=BARKS, HOME=HOME. Psych Chain knobs: Drive=GROWL, BBD=ALLEY, Spring=DRAIN, Tape=CHEW. Banks: THE
POUND (locked factory) / THE PACK (live). FLEAS = the degradation dial (CLEAN/ITCH/SCRATCH/MANGE).

## 6. THE SOUND

**The Psych Chain** (after voices, before the master VCA gate), reached by FX:
`VOICES → PREAMP DRIVE (new) → BBD DELAY (re-voiced, free-ms; REC was tap-tempo until Batch 9B, now HOLD) → SPRING REVERB (re-voiced) →
TAPE DEGRADE (new) → MASTER GATE`. The 3 freed chorus param slots (`P_CHO_*`) carry Drive + Tape; no new
patch storage. Build Drive/Tape as integer fixed-point.
**DRIVE (GROWL) — DONE** (`obv_drive.h`): on the voice bus before the output stage; the 3 chorus bytes are GROWL (54,
CC 69), BIAS (52, CC 67), TONE (53, CC 68), so **Tape takes bytes from the 64..79 gap** (no byte or CC moves). KNOB 1 on
DRIVE, SELECT held = DRIVE + (BIAS, TONE). 4x oversampled tanh-table clip, pre-clip low-pass closing with GROWL, loudness
held within ~0.6 dB 0..100 % (K-weighted trim), GROWL 0 a bit-exact bypass. Measurements: `listen/drive/README.md`,
`dog5-docs/PERF-BASELINE.md` (742 host instr/sample). The six factory patches that had chorus on (10, 12, 13, 16, 24,
29) are at GROWL 0, with width compensation (approved 2 Nov): 10/12 SPREAD 100; 13/16 LFO PITCH 3; 24 LFO PITCH 4 +
DLY MIX 35; 29 unchanged otherwise.
**TAPE (CHEW) — DONE** (`obv_tape.h`): bytes **64–67** (CHEW, WOW/FLT, HISS, DROPS; CC 83–86, appended, no byte or
CC moves; 68–79 stay free). **For now it sits last, after the (old) reverb** — final order waits for the BBD/Spring
re-voice. KNOB 1 on TAPE = CHEW, SELECT held = TAPE + (WOW/FLT balance, HISS ±12 dB, DROPS ×0–3). Wow (1.4 % peak at
the top) → flutter (from 20 %) → dropouts (from 45 %), with tanh saturation, head loss and bump rising; 2x line with a
fitted 6-point read (no aliasing from the wow: `listen/tape/README.md`), a fixed 3.6 ms head (a CHEW turn never bends
pitch), the hiss rests 2 s after silence, loudness held within ~0.3 dB (static law + K-weighted trim), CHEW 0 a
bit-exact bypass. ~960 host instr/sample (the most of any stage: levers in `dog5-docs/PERF-BASELINE.md`), pool +4 KB.

**BBD (ALLEY) — DONE** (`obv_fx.h`, branch `claude/psych-bbd`): OberVave's ping-pong delay re-voiced in place (after the
output stage, before the reverb). Bytes **68–70** (ALLEY, FINE, PINGPONG; CC 87–89, appended; 71–79 stay free); the old
TIME byte 55 is now SYNC, the note value **ALLEY 0** follows (so the 8 factory patches with the delay on keep their
times). KNOB 1 on BBD DELAY = ALLEY: 10–740 ms free (3.5 % a step; leaving SYNC starts from the time sounding), SELECT
held = BBD + (SYNC, FINE, PINGPONG); **the REC tap tempo (mean of 3 intervals, folds to its 8th) was removed in Batch 9B:
REC is HOLD now (§5); FINE stays, ALLEY's knob is unchanged.** Each pass is band-limited as a BBD's (2-pole + 1-pole,
8 kHz at 10 ms → 2.8 kHz at 740 ms), TONE stays in the loop, an 80 Hz high-pass thins the repeats, tanh headroom on the
line and in the loop; FEEDBK keeps the old law to 112, holds at ~120 and runs away above (settling under full scale). A
time change bends the repeats' pitch (≤ −12 / +7 semitones, eased: never a click). MIX 0 is the old delay's bypass,
bit for bit. Buffer unchanged (743 ms a side), CPU 310 host instr/sample (old 109), all four stages 2,588.
`listen/bbd/` has the measurements and the kit. **The reverb has a pre-existing overflow** at REV_MIX/SIZE 127 with a hot
input (`rev_tick`'s output taps × 19661), on `main` too: left for the Spring re-voice.
**Spring reverb:** re-voice the Dattorro plate *toward* spring — allpasses faster+shallower, short PRE-DLY,
brighter DAMP, clamp SIZE so it can't bloom into a hall. **Excellence is NOT required** (Vincent has real
analogue units); "the next closest thing" is explicitly enough. `REV_DIV 2` (half-rate) is the CPU lever. **DONE** (`claude/psych-spring`, DRAIN on SPRING
KNOB 1 = the old MIX byte 62; SIZE / DAMP / PRE-DLY on SELECT held; a 66 ms tank, chirp chains of 5-sample allpasses,
SIZE 0.3–3.0 s, PRE-DLY 0–35 ms; DRAIN 0 bit-exact; pool −69 KB; `listen/spring/`). The plate's tap-sum overflow is
fixed (clamp); with CHEW on, the effects hand it their sum unclipped and its record stage has its own knee. FX held =
GROWL / ALLEY / DRAIN / CHEW.

**Variable polyphony — `P_POLY_N`, range 1–8, default 5. DONE** (on VOICE +; `poly_n()` in `obv_engine.h`;
tests/poly.txt). It clamps the **POLY/DUAL** allocation window (`voice_alloc`), so a chord steals once the
window fills — the voice-stealing character. **UNISON/MONO keep their own count (`P_UNI_N`), so no existing
patch's sound changes** — the `part_cards` window the brief assumed went with track B, so the clamp lives in
`voice_alloc` now. At `P_POLY_N = 8` the allocation is **byte-identical** to before the parameter existed
(proven against the session-start build). It won't speed up normal playing (idle voices are already skipped) —
what it buys is a worst-case CPU ceiling for POLY playing and the stealing character; it settles 5-vs-8 by
ear on the device. Ships at 5 (keeps the five-motif: POLY 5, Fi(l)fth, 5th quadrant). It is byte 63 of the
patch record (appended; MIDI CC 82; the earlier CCs are unchanged).

**Note-event latency — resolved, inherited.** Upstream fixed note timing in 1.4.2 (notes are serviced
inside the LCD's DMA wait via `app_idle`). We inherit it by pinning 1.5.3. **The one DRAW RULE going
forward: every DØG-5 draw routine that waits (on DMA, a fill, a blit) must call `app_idle()` in its wait
loop.** No new drawing code may block without yielding to notes. That is the whole mitigation.

## 7. THE PRESET BANK

- **99 slots** (inherited). **A/B as a write-lock, not a store expansion:** lock slots 1–32 (factory, THE
  POUND, write-protected) vs 33–99 (live, THE PACK). The factory bank is now the 32 DØG-5 patches
  (`NFACT 32`); the old "expand to 64" plan is obsolete — 99 is bigger, and the factory half tracks the
  32-patch bank, not 64. **The write-lock is DONE (Batch 15, `prog_get` / `pack_free` / `pound_rescue` in `obervave.c`;
  tests/controls/write_lock.txt, the store selftest):** programs 1–32 always read the factory (a firmware update brings its
  voicing); SAVE armed on a POUND slot offers the first free PACK slot, on a PACK slot that slot; PRESETS while armed moves
  through 33–99 only (99 ↔ 33). The store below the lock is unchanged (all 99 slots, 3 sectors). Once at power-on, a save
  over 1–32 from before the lock (v0.1 / v0.2) moves to the first free PACK slot; with THE PACK full it stays, unread.
- **Name field widened 10 → 14 characters and `PATCH_BYTES` grown 80 → 96 — DONE** (§4, committed). The
  14-char name plus DØG-5's new params (Tape 2nd macro, `P_POLY_N`) hit 79/80 at 80 bytes — one spare,
  which a planned v1.1 couldn't extend without migrating every patch. The 96-byte record (name at a fixed
  offset `PATCH_NAME_AT 80`, 14 bytes, then 2 spare) costs ~1.6 KB flash (16×99) and buys 2 spare bytes now
  plus the whole 63..79 parameter gap (NPARAM 63) for growth. The store carries a new `"DOG5"` version tag,
  so old 80-byte data is never misread; **42 patches per 4 KiB sector, 3 program sectors** hold the 99
  slots. Done before any patch existed (free migration).
- **The 32 patches** and their SOUND briefs are locked (`dog5-docs/DOG-5-presets.md`). Voice them by ear on the
  host build. Minimum gig set defined there if time bites. ~Half are buildable before the Psych Chain exists.
- **4 names changed** for the 14-char fit (and taste): 09 Skinhead Bubble→**Skeenhead**, 17 North Water
  Ice→**Titanic**, 18 Rotoscoped Void→**Roto-scopo**, 19 Blackwater Tank→**Blackwater**→(dropped 6 Nov) **Micro-mist**. All other names fit
  at 14 untouched. Longest in the bank: Atlantic Swell / Slapback Strut (14).
- **Fix the font for Ø first** (§4) or `THE DØG` shows as `THE D?G`.

## 9. THE DEV ENVIRONMENT (how this gets built)

- Build machine: **Claude Code cloud sessions** (claude.ai/code) pointed at this repo, driven from a browser
  (the owner's iMac is on macOS 12 and can't run Claude Code or Docker locally). The iMac flashes the FM-1
  from Chrome via the Firmware Hub when the unit arrives. git/GitHub is the bridge.
- **Host build + browser sim need only clang + Python + Pillow** — all present in a default cloud env. The
  whole synth, the Psych Chain, patch voicing and the art can be built and heard/seen there with no special
  setup. `tests/run_host.sh` (WAV + screen PNGs), `web/sim/build.sh` (browser).
  **Browser player (Batch 8B, live at `docs/play/` = `https://vincentzsk-prod.github.io/dog5/play/`):** `sh web/sim/build.sh`
  builds the unchanged firmware + `web/sim/sim.c` to `docs/play/dog5.wasm` (zig cc, then Binaryen `wasm-opt --asyncify`) and copies
  the page (`index.html`, `sim.js`, `sim.css`, `worklet.js`) and `patches.json` (the 32 factory names, read from
  `obv_patches.h` by `web/sim/gen_patches.py`). Tools, installed by hand once (the script installs nothing and prints the
  commands): `python3 -m venv ~/.local/share/obervave-wasm && ~/.local/share/obervave-wasm/bin/pip install ziglang`, and
  `npm install --prefix ~/.local/share/obervave-wasm/npm binaryen` (wasm-opt 132; the script finds it there). Test:
  `node tests/sim_test.mjs` (default `docs/play/dog5.wasm`; sound is checked bit-for-bit against the host build). The sim keeps
  **12 storage blobs** (settings, 8 pattern sectors, 3 program sectors; a store of any other length is ignored) in localStorage
  key `dog5-sim-store-1`. The page picks a patch with a MIDI program change on the MIDI channel set on GLOBAL (`sim_pick`, Batch 14). No analytics.
  (OberVave's own simulator build, `tests/ref-sim/`, was removed in Batch 12B; it is in the git history.)
- **The device build (`.fwsc`) needs two JieLi downloads.** Re-tested 2026-11-02: the original hosts work
  fine from this cloud environment once `pkgman.jieliapp.com`, `gitee.com` and
  `jl-update.oss-cn-shenzhen.aliyuncs.com` (the redirect target the toolchain link lands on) are allowlisted
  in the cloud environment's network settings:
